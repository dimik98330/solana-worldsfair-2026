## Five focused priorities

1. **[P1] Выбор вкладки эмитента подменяет просмотр созданием.** Для незнакомого судьи существующий completed issue превращается в пустую форму, потому что кошелёк не является issuer. Source App.tsx:23/:213 + IssuerSetup.tsx:59, observed entry/Issuer. По умолчанию показывать существующий выпуск read-only с одной ясной New issue action; форму начинать только по явному выбору. Пустой новый workspace может по-прежнему вести к созданию. Это routing/presentation fix, не ослабление permissions.

2. **[P1] Disabled actions и identity copy не объясняют реальную причину.** Registry Capture record date и Voting Create proposal disabled без причины; voting делает утверждение о правах невыбранной identity. App.tsx:217/:220, current registry/voting/account observations. Разделить no account / wrong authority / closed lifecycle / already voted / pending recovery / RPC unavailable и показать короткую причину рядом. Доступ уже реализован — исправить объяснение, не enable gates. Payments Add reserve служит существующим хорошим образцом с aria-describedby.

3. **[P2] Несогласованный date/time presentation усложняет точное чтение.** Payments: `8 Oct 2026` + `04:14:37` + `Times in UTC+5`; Overview/Registry/Voting/Receipts: `08 Oct 2026, … GMT+5`; создание: `Asia/Qyzylorda`, review иногда без seconds. Действующие source locators: PaymentsWorkspace.tsx:24/:53, format.ts:57–61, IssuerSetup.tsx:253/:297, DateTimeField.tsx:51. UTC+5 и GMT+5 равны в текущем окружении; ошибка сдвига сейчас **не обнаружена**. Но timezone label Payments берётся от `new Date()` сейчас, а сама дата форматируется для её timestamp: другой DST offset — source-supported риск, rendered behavior не проверено. Использовать один display-timezone preference: default browser zone, понятное имя с offset, optional выбор в account/display settings; хранить исходный UTC timestamp, применять единый IANA zone ко всем датам. Для каждой важной пары — стабильные date/time строки и точные seconds; не заменять timestamp лишь красивым коротким текстом.

4. **[P2] `100% paid` bar повторяет уже полную финансовую сверку и выглядит как общий completion meter.** Observed below-fold Overview и App.tsx:273–275/styles.css:228–235. Это отношение paid/entitlement latest coupon (900/900), а не readiness/stage progress. Заменить bar компактной строкой **Coupon 1: paid in full** рядом с exact totals; partial state — конкретный unpaid amount, а не ещё одна длинная линия. По source format.ts:44 missing/invalid/zero denominator возвращает numeric 0; при любом сохранённом проценте отдельно различать unknown и genuine 0%, не заменять Money/BigInt на floating point.

5. **[P1] RU copy теряет часть proof scope и остаётся неполной.** ui-language.tsx:7 переводит EN note о separate confirmation / older retained receipt только как «Здесь находятся подписанные операции и их подтверждения». Это source-confirmed потеря оговорки; RU rendered view данной Assessment не проверен. App.tsx:216/:263/:268/:220/:286 содержит несколько динамических English detail strings вне `t` (circulation/placed/payment frequency/proposal eligibility/claim detail). Привести ключевые state/help строки к EN/RU parity, особенно signed ≠ confirmed now и retained historical proof. Не переводить идентификаторы и не скрывать exact localnet/signing scope. Decimal/thousands locale можно улучшать только при сохранении exact integer/string arithmetic.
