## Пять приоритетных изменений

1. **[P1] Вход показывает создание вместо результата.** Добавить стартовое read-only знакомство с существующим выпуском, компактным назначением продукта и тремя KASE-сценариями. Основная кнопка ведёт в Payments выбранного реального выпуска; secondary — создание. Ссылка должна содержать существующий instrument address. Не создавать новый выпуск автоматически. Команды: Impeccable onboard/shape.
2. **[P1] Роли и состояние объясняются слишком поздно или неточно.** Свести причины unavailable к понятным состояниям: аккаунт не выбран, другой issuer, rights ещё не записаны, время не наступило, событие закрыто, операция требует recovery. Closed voting и fully settled issue показывать как завершённые события, а не пустой набор disabled buttons. Source показывает нелокализованные NextActionDesk, footer Voting и ErrorNotice; привести их к существующему EN/RU механизму. Команды: clarify/harden.
3. **[P1] Нет одного правила для дат и timezone.** Payments показывает UTC+5 на отдельной строке; Registry/Overview/Voting/Activity используют плотную строку с GMT+5; Schedule/Review — Asia/Qyzylorda. В foreground календаря timezone отсутствует. Применить единый DateTime display, добавить display preference и ясную timezone внутри calendar/review. Команды: clarify/typeset.
4. **[P1] Квитанции требуют технической расшифровки.** В read-only пути связать запись выплаты с фактическими правами и доступным подтверждением. Данные Activity ограничены kind/time/status/signature/explorerUrl: использовать честную детализацию, не выдумывать recipient/amount из соседней строки. Exact localnet и signer scope оставить в details. Команды: shape/clarify.
5. **[P2] Длинная полоса 100% повторяет уже понятный финал.** На Overview она выглядит как механический progress widget между точными итогами и Paid rows. При полном расчёте заменить её компактным текстом «Выплачено полностью · 900 из 900», при необходимости «3 из 3 получателей». Для промежуточного состояния допустима тихая полоса с точным текстом рядом. Не менять формулу/деноминатор. Команды: distill/layout.

Подтверждённых P0 в пределах этого frontend-аудита нет: существующие выплаты и квитанции доступны без кошелька. Это не утверждение об отсутствии P0 в backend, подписи или конкурсной подаче.

## Время: UTC+5 и настройка в аккаунте

UTC+5 на этой машине — наблюдаемая корректная подпись текущего отображения; сама по себе она не ошибка. Проблема — три разных способа подписать время и отсутствие контроля у другого читателя.

- В account/display дать «Часовой пояс отображения»: системный, выбранный IANA zone, UTC. Начальное значение — системный; текущий здесь Asia/Qyzylorda / UTC+5. Предпочтение локальное, доступное без wallet и без сервиса/денег.
- Во всех work screens использовать одно представление: `8 окт. 2026` и отдельная строка `04:14:37`; один timezone note для группы, например «Время: UTC+5 (Asia/Qyzylorda)». Не повторять GMT после каждой строки истории. Полный исходный instant/UTC остаётся в time/title/details.
- В календаре timezone должна быть видна рядом с временем/Selected, а не только на затемнённом background. Полноценный Review сохраняет секунды и исходную точность; source уже сохраняет ненулевые секунды — потери данных этим аудитом не обнаружено.
- Переключение отображения **не сдвигает** record/payment/maturity instants. Сейчас editing парсит browser-local datetime. Поэтому первая безопасная версия preference — отображение существующих записей; creation ясно сообщает собственную timezone. Если редактор тоже начинает использовать выбранную zone, ему нужна согласованная конверсия и проверка DST/неоднозначных локальных дат. Простое добавление `timeZone` только к formatter было бы недостаточным.
- Для test lifecycle точные секунды остаются доступными; «через 15 минут» — помощник заполнения, а не доказательство исполненного действия или замена deadline.
