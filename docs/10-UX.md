# UX-направление BondTrace

Профильные навыки: frontend-design, design-taste, frontend-design-guidelines, product-review; бренд выбирает ведущий в рамках поручения пользователя «красивую ... реализацию». Интервью о палитре не должно блокировать выбранную конкурсную задачу.

Направление: финансовый операционный кабинет, точная сетка, светлые нейтральные поверхности, графитовый текст, один кобальтовый акцент; крупные табличные цифры, ясные статусы и немного структурной графики. Рабочие цвета/типографика фиксируются в brand.md. Без декоративных крипто-градиентов и выдуманной telemetry.

Главный визуальный приём: lifecycle полоска инструмента и реестр выплат, где видно snapshot → entitlement → settlement → proof. Для issuer — обзор, holder registry, action review, confirmed results; для investor — portfolio, coupon/redemption и voting. Ценность видна через реальную связь количеств/сумм/операций.

Каждая подпись предваряется summary: действие, сеть, authority, получатель, сумма, fee. Wallet cancellation не ошибка chain; timeout ведёт к проверке уже созданной signature, не новой выплате. Empty registry отличается от unavailable RPC. Предложенная sample data явно помечена demo/test.

Кошелёк в обычном режиме управляет пользовательскими подписями. Если предусмотрен обучающий demo signer, он отдельный, тестовый, явно маркированный и не требует личных ключей. Никакого скрытого управления средствами пользователя на backend.

Основные controls работают keyboard/touch; таблицы на телефоне превращаются в понятные карточки/scroll зоны. Адрес доступен полностью перед подписью; суммы integer-formatted, сеть постоянно видна. UI QA через реальный браузер на desktop/mobile, не только CSS чтение.

## Реализованный интерфейс — 07.10.2026

Файлы интерфейса: `C:\Users\dmitrii\Documents\solana\apps\web\src`. React/Vite SPA содержит Overview, Holder registry, Payments, My portfolio, Voting и отдельную панель Proof & activity. Английские подписи предназначены для демонстрации международному жюри; названия инструмента и proposal читаются из API без замены выдуманными данными.

Swiss-направление: один шрифт Helvetica/Arial, neutral `#F7F7F8`, white panels, cobalt `#002FA7`, тонкие правила сетки. Кобальтовая карточка инструмента и lifecycle rail связывают реальные сроки, текущую позицию, snapshot и результат выплаты. Финансовые числа используют tabular numerals выбранного единого шрифта. Полные 6 decimals намеренно сохранены вместо рыночных сокращений/оценки USD: у тестового settlement mint нет подтверждённой рыночной цены.

Первый полезный шаг — Create test instrument. Guided demo и My wallet — разные видимые режимы; переключение роли означает generated test signer, а не подключение личного кошелька. Wallet Standard обнаруживается через Kit wallet plugin; выбранный signer подписывает точные подготовленные байты только после успешной RPC simulation и review. Версия берётся из фактического сообщения; v0 допускается, v1 проверяется по поддержке wallet. Изменённое кошельком сообщение отклоняется до relay.

Scheduled coupon не называется неизменяемым entitlement. Пока snapshotAddress отсутствует, это расписание; после capture отображается fixed coupon registry. Record date и maturity controls сверяются с chain serverTime, состояние читается каждые 12 секунд только в видимой вкладке. Сеть, signer, token mint, получатель, точная сумма и реальная fee из подготовленного API показываются до личной подписи. Bond transfer отображает целое число bonds при tokenDecimals=0.

Защита от повторов: операция сохраняет recovery reference до POST; pending/unknown закрывает новые изменения. GET operation/signature проверяет уже созданную операцию, без новой подписи. Lost response не считается подтверждением и не вызывает автоматический retry. Закрытие страницы сохраняет незавершённую операцию в localStorage без секретов. Cancelled signature отделена от network error. Реальные подписи доступны полностью и через Solana Explorer; API state mainnet/другой сети отвергается.

После погашения New test issue создаёт новый тестовый выпуск через reset bootstrap; предыдущие on-chain аккаунты и история сохраняются. Демонстрационные сроки отмечены как accelerated. Личный wallet flow не проверяется с реальными средствами.

Проверки frontend: `npm run typecheck` — passed; `node --import tsx --test apps/web/src/format.test.ts` — 3 passed (6 decimals, BigInt/ввод, разрешённый HTTPS Explorer). Browser QA desktop/mobile и полный UI flow выполняет ведущий отдельно; исходники/CSS сами по себе не считаются доказательством UI QA. Продолжение и результаты — `docs/research/kase-ui.md`.
